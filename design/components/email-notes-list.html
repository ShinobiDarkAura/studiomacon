31px is an outlier: the closest sizes elsewhere are the email code at 30px (--t-code) and the footer's fine line at 30.4px (--t-fine). All three are close enough to look like a typo of one another, but each is a distinct, deliberate value — none has been unified into a shared token yet.

Phones

No phone-specific override for notes() in build_emails.py — the 244px column and its type sizes stay fixed; only the outer .pad 24px side padding is standard across all rows.

Do / Don't

Do
  • Keep each note to a short title (one or two words) and a single short paragraph.
  • Use notes() in pairs or trios — it always groups related short answers.
  • Keep the 244px column centred; it is deliberately narrower than the page's other text blocks.
Don't
  • Don't round 31px down to 30px to match the code box or footer fine line — it is its own size.
  • Don't widen the notes column to match the 294/338/378px text() widths; it is a distinct, narrower measure.
  • Don't drop the 42px gap between rows — the notes read as one another's neighbors, not as a bullet list.
